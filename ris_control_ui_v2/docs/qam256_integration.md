# 256QAM 码本接入新 RIS 控制台的方案

本文为初期评估。最新实现、配套文件和使用步骤见 [完整链路说明](qam256_end_to_end.md)；原速限制仍适用。

评估日期：2026-10-30。源数据：项目根目录的 `ris_256qam_codebook_0deg/`。

**建议将码本作为“MT时域控制”里的“400路独立 / 256QAM”子功能接入，沿用总下发按钮。导入、参数查看、星座/PWM/阵列预览可以在 GUI 层完成；默认1 MHz、256时间片的真实256QAM播放，需要扩展 FPGA/固件，现有统一MT或软件图案播放器无法直接承担。**

上位机现已完成下文第一阶段：码本导入/验证、目标星座/PWM/阵列预览、数据源与K配置、方向/极性设置、总按钮静态核线，以及离线播放包导出。使用说明见 `qam256_host_usage.md`。真实256QAM连续播放仍未接入板端协议，也未修改或下载板端程序。下文保留后续板端设计依据。

## 已核对的数据

审计工具为 `../tools/analyze_qam256.py`，结果保存在同目录的 `qam256_audit.json`。已核对6个文件的 SHA-256，验证全部65,536幅二进制图案与102,400条脉冲参数逐幅一致，并检查256个符号的 Gray 标签和400个单元的坐标。

| 项目 | 当前导出内容 |
| --- | --- |
| 扫描方向 | 仅0°，当前包不含±45°码本 |
| 阵列 | 20×20，共400个单元 |
| 符号 | 256个；每字节高4位是I的Gray标签，低4位是Q的Gray标签 |
| PWM | 1 MHz，每周期256片；每片3.90625 ns |
| 符号保持 | 每个符号重复3个PWM周期；333.333 kSymbol/s，裸比特率2.667 Mbit/s |
| 帧大小 | 每片50字节；一个符号的一个PWM周期12,800字节 |
| 总帧数/大小 | 65,536帧，3,276,800字节，即3.125 MiB |
| 实际最短非零高脉宽 | 5片，即19.53125 ns；这与README中的连续解约21.24 ns是不同的量 |
| 实际最短整板图案更新间隔 | 1片，即3.90625 ns |
| 按现有FPC分组后的最短更新间隔（假设row0在上、col0在左） | 同样存在1片间隔，不能靠10组分开控制就消除时序冲突；物理方向仍待确认 |
| 每符号不同单元PWM参数的数量 | 55–79种，显然不是全400路统一波形 |
| 模型均衡EVM | 元数据给出约0.3143%，属于理论模型值，不是实测接收结果 |

这个包是一张“方向×符号”的波形字典，**不是已经指定好顺序的待发数据流**。`symbols.csv` 按0到255列出查表标签，并不要求实际按0到255发送；还需配置固定符号、符号列表、二进制数据文件或测试序列。

二进制只存每个符号的一个PWM周期；K=3由播放器重复，不能漏掉这一步。每个单元状态按 `((q-r) mod 256) < p` 重建，跨周期边界的高脉冲必须按原规则回绕到该周期内。

## 新GUI中的位置与操作

主下拉菜单仍保持原来的四个大类。在“MT时域控制”页增加控制类型选择，只显示当前类型的配置：

- 400路统一MT：保留现有功能和原协议。
- 400路独立 / 256QAM：显示以下码本配置面板。

建议独立码本页面分为四块：

| 配置区 | 内容 |
| --- | --- |
| 码本 | 导入目录或ZIP、文件校验、阵列尺寸、方向、载波与PWM频率、L、K、模型说明。当前包只显示0°。 |
| 发送内容 | 固定字节/符号列表/二进制文件/测试序列，播放一次或循环；显示符号数量、预计时长和实际符号率。 |
| 预览 | 256QAM星座与所选符号、所选单元的PWM、时间片q对应的整板20×20图案；区分理论波形和硬件编译后的波形。 |
| 兼容性 | 当前固件支持哪些功能、映射是否完整、方向/状态极性是否确认、实际时序是否满足、编译量化后的误差。 |

码本自带的PWM频率、L和物理模型先作为只读来源参数。K可以作为播放参数单独设置，并显示其对符号率的影响。需要更改PWM频率或重新量化时，必须生成新的目标配置/码本记录，不能静默改掉元数据或直接把现有波形拉慢后仍标成原方案。

导入、选择星座点、拖动时间片、设置数据源、预览、方向/极性编辑都只修改配置。原来的右上角“下发指令”是唯一应用入口：

```mermaid
flowchart LR
  A[码本及待发数据] --> B[本地校验与预览]
  B --> C[方向与FPC映射转换]
  C --> D[板端能力与时序检查]
  D --> E[点击总下发按钮]
  E --> F[上传完整播放包并校验]
  F --> G[FPGA本地执行]
  G --> H[状态回报]
```

状态屏可增加“256QAM上传中”“256QAM单符号循环”“256QAM数据播放一次/循环”“播放完成/停止”等状态。频率、K、方向、符号计数和活动码本标识由板端回报，配置草稿不覆盖已运行状态。

保持当前GUI的运行快照原则：下发后编辑码本、数据源或映射，只影响下一次下发。上传中止或校验失败，不允许启动半套数据。停止和取消仍通过总按钮应用。

## 必须经过空间映射和状态极性转换

导出文件中的 `unit=row*20+col` 是空间位置，二进制低位优先打包。现有控制器的50字节按595芯片/Q引脚排列，**两者虽然都是50字节，排列含义不同，不能直接发送原始帧**。

处理顺序应为：

1. 确定码本坐标相对实物的方向：元数据只说明row0在负y、col0在负x，没有说明哪边对应实物BIAS上边。用三个角标识确认旋转/镜像关系。
2. 确定码本状态1对应驱动高还是驱动低。Gamma0/Gamma1是射频透射系数，不等于已经确认了GPIO极性。
3. 将空间位置转换成现有GUI的RIS行列，再通过已保存的FPC—RIS映射换成芯片/Q位。
4. 要求完整400路映射；未经实测确认的手动映射继续沿用原规则，不开放实际输出。
5. 将方向、极性、映射和码本的标识一并写进播放包，避免后续错配。

举例：**仅假设码本row0对应GUI最上行**，当前保存的映射中，`unit=1` 是R01C02，原包位于byte0/bit1，实际板端却是byte1/bit2。在该假设下400个位置中399个需要换位。这只说明必须重排，不能作为物理方向已确认的依据。

方向和状态极性应放在“全板设置”中集中配置，码本页显示所引用的设置，并提供角标预览。

## 当前输出链路的具体差距

| 层次 | 现有实现 | 码本需要 |
| --- | --- | --- |
| 统一MT | 每段只有一个电平和持续时长，全部400路相同 | 每个时间片的完整400位图案，或者等价的400路独立PWM参数 |
| 高速输出 | 50条DS广播同一个数据值；每次8个100 MHz移位脉冲及锁存，至少100 ns | 当前包出现3.90625 ns的图案变化，含19.53125 ns高脉冲 |
| 普通图案 | 普通FRAME命令、软件确认与停留时间；当前图案列表最低100 ms | 硬件定时的纳秒级连续输出，不能靠逐帧TCP/GUI计时 |
| 时钟量化 | 时序引擎300 MHz，时钟约3.333333 ns | 1 MHz×256片=256 MHz均匀时间网格；每片是300 MHz时钟的1.171875倍，不能直接用同一整数分频精确表示 |
| 存储 | 当前MT构建16个普通帧槽，另有2048段统一MT RAM | 当前码本有1119种不同空间图案，并需要完整符号调度/持续时间表 |

这些限制来自本项目实际RTL/固件，不是仅根据“1 MHz”名称作判断。`rtl/ris_fast_io.v` 使用 `{50{fast_data}}` 广播；`rtl/ris_mt_engine.v` 每段只有 `{level,duration}`。普通FRAME能力不能替代独立400路的高速播放能力。

5.8 GHz是入射射频载波；本方案由RIS的PWM产生相应谐波。问题在于驱动状态变化的时间精度和输出链路，而不是让FPGA直接生成5.8 GHz。

## 板端扩展建议

增加一个与现有统一MT并存的“独立图案时序播放器”。GUI在下发前完成码本导入、位重排、去重、时间编译及完整流的边界检查；TCP用于预装载，FPGA在本地播放，避免网络逐片调度。

当前数据有一个有利特点：65,536帧只有**1119种不同图案**，可编译为：

- 图案字典：1119×50=55,950字节；实际RAM布局可按64字节等方式对齐。
- 符号事件表：每个符号从q=0开始按连续相同图案合并，合计26,103段。假设每段用16位图案索引+16位持续片数，约104,412字节。
- 二者裸数据合计160,362字节，约156.6 KiB，另加符号偏移表、头部、校验、对齐和待发字节流。

上述编码可完整重建当前包，不是删掉短脉冲或降低精度。它解决存储和预装载问题，**不解决输出速度限制**。另一个备选是保存400单元的p/r参数：当前包约200 KiB，再由硬件独立产生波形；哪种方式更合适，应通过资源、预取和时序综合比较。

建议新增独立能力回报字段，例如 `qam_supported`/`vector_supported`、最小更新时钟数、字典/段表容量、实际频率、活动包标识和播放位置。它们目前尚未实现，不能把现有 `mt_supported=true` 当作256QAM可用。

上传协议需要表达暂存、完整性校验、提交和启动，具体指令名后续设计。原有STATUS/STOP及其他控制入口继续兼容，新能力不能改变旧MT表的含义。

## 先做到哪一步

**第一步：GUI导入与预览，以及静态码片检查。**

导入现有包，检查哈希/结构，显示星座、单元PWM、时间片阵列和映射结果。可通过总按钮下发某一时间片的静态图案，用于核对空间映射与极性；必须标为静态检查，不宣称产生了256QAM射频信号。本阶段可以保持现有BIT/ELF不变。

**第二步：扩展独立图案播放器，先验证较低PWM频率。**

若新任意图案引擎经过设计与实测，也能做到每100 ns更新一次，那么保留L=256、最短1片变化的理论上限为：

`fPWM <= 1 / (256 × 100 ns) = 39.0625 kHz`

在300 MHz时钟下，39.0625 kHz恰好每片30个时钟，K=3时约13.0208 kSymbol/s、104.167 kbit/s。先用19.53125 kHz（每片60时钟、200 ns）可留出更多验证余量。这些是**新独立图案引擎的候选设计点，不是现有固件已经支持的发送模式，也不是已经验收的硬件性能**。

频率变动会改变谐波频率、接收滤波条件及模型中的输出波数，应重算/复核码本和EVM。当前目录是导出结果，未找到README提及的 `ris_codebook_gui.py` 生成器源文件；预览可直接使用CSV/BIN，重新生成则需取得生成器或另行实现并验证。

**第三步：若必须保留原1 MHz、256片方案，再单独评估输出架构。**

现有100 MHz移位与锁存链路不能实现这份包出现的3.90625 ns相邻图案变化。单纯增加GUI按钮、改TCP命令或增加缓存均不能补上这项能力。需要重新评估更快的输出/驱动架构，或明确允许的量化误差后重新设计码本；不能直接声称原约0.3143%模型EVM依然成立。

真实256QAM验收还需要完整符号序列边界测试、示波器确认输出时间/极性，以及射频接收端的同步和解调EVM验证。源包的模型EVM不包含这些测量。
