# RIS 控制台 v2

这是原版控制台（现位于 `../legacy_mt_host`） 的独立界面副本，本目录保存上位机源码、映射、图案库、MT示例、测试和截图；板端代码单独位于 `../../FPGA/ris_qam_backend`。原控制台和原数据文件保持不变。

## 启动

统一从项目内部启动：

```bash
/home/wenhan/PROJECTS/RIS/RIS_CTRL/ris_control_ui_v2/start_gui.sh
```

默认只打开界面，不连接板卡。界面中的 IP、端口和连接方式沿用原版：`192.168.1.11:7060`，电脑有线网卡为 `192.168.1.20/24`。

SOFTWARE中的旧启动器和本目录原有的安装器模板已移除；直接使用本目录的 `start_gui.sh`。

运行库和依赖包保存在 `/home/wenhan/SOFTWARE/RIS-GUI-V2/runtime` 与 `packages`，原版运行库也保留在 `/home/wenhan/SOFTWARE/RIS-GUI/runtime`。两处旧启动入口已移除。系统 Python 已包含 Tkinter 时，也可直接运行 `ris_gui.py`。可用 `RIS_GUI_RUNTIME` 指定其他兼容运行环境。

可选启动参数：

```bash
./start_gui.sh --mt
./start_gui.sh --qam
./start_gui.sh --codebook /path/to/codebook.zip
./start_gui.sh --patterns
./start_gui.sh --mapping
./start_gui.sh --mapping-file /path/to/mapping.json
./start_gui.sh --connect
```

`--connect` 只建立连接并读取状态，输出配置仍需点击总下发按钮。启动时默认读取本副本的 `mappings/ris_mapping.json`，不自动应用图案。

## 使用方式

1. 在主页面的“功能”下拉菜单选择大类，进入独立配置页面。
2. 配置模式、参数或测试对象；右上角显示“待下发”摘要。
3. 点击显示区旁的“下发指令”，将当前页面的配置应用到板卡。
4. 等待板端确认，在深色显示区查看当前实际工作状态。

主菜单固定为 **全板控制、MT时域控制、图案切换控制、全板设置**。每次只显示一个大类页面，切换后保留各页草稿。总按钮只应用当前页面；全板设置中也只应用当前设置选项的配置。

各模块的按钮均为配置操作，包括停止、单元测试和芯片字节配置。选择模式、修改数值、载入文件、预览、编辑映射、编辑/保存图案、选择上一项/下一项，都不会直接发送输出指令，也不会停止正在运行的循环。**停止同样需要先选择停止，再点击总下发按钮。**

参数范围、固件能力和映射校验在执行前完成。新配置无效时，当前运行继续保持。总按钮点击后才会接管原有输出；正在处理其他指令时需等待确认。

## 四类功能

| 页面 | 配置内容 |
| --- | --- |
| 全板控制 | 全0保持、全1保持、停止/保持、全0/全1慢速循环、FPGA 硬件方波；单元电平、单路检查、单芯片/5片组字节配置。 |
| MT时域控制 | 独立子页：统一400路MT；400路独立/256QAM码本、数据、静态核线与一次/循环播放。均经总按钮应用。 |
| 图案切换控制 | 20×20图案绘制、行列编辑、图案库导入导出、播放列表、各项停留时间、顺序一次/顺序循环/往返循环/随机循环、单项选择。 |
| 全板设置 | 输出使能/高阻、FPC—RIS 映射、通信日志。映射内保留接口绑定、逐点标定、明细、恢复草稿和接线测试。 |

全板控制默认显示全板模式，勾选“切换到单元 / 芯片配置与接线检查”后，单独显示局部配置面板。芯片 HEX 与 Q 位继续联动；选择配置后再修改字节，总按钮应用修改后的数值。

慢速切换间隔保持 `100–60000 ms`。硬件方波频率保持 `1 Hz–5 MHz`，继续使用原300 MHz整数分频和量化规则；两类页面的频率参数独立保存。400路独立/256QAM使用新副本配套的QAM1 BIT与网络ELF，详见下文。

图案和列表在总按钮下发时形成完整运行快照，包括图案字节、顺序、模式和每项时长。播放中可以编辑下一次配置、调整列表或更改映射；当前播放仍按已下发的快照执行。再次点击总按钮后应用新配置。软件图案播放仍从每项板端确认后计时。

映射标定中的“记录后预选下路测试”仅选择下一通道并准备待下发测试，必须再按总按钮才更新输出。实测确认仍要求当前通道已得到板端测试确认。已配置单元后若修改映射，需重新选择测试/电平配置，避免旧映射被误用。

MT 上传时，“选择取消上传”只配置取消请求；随后总按钮变为“取消上传并停止”。点击总按钮后，在当前应答完成后停止上传并确认 STOP。即使取消恰好发生在最后的启动应答期间，也会补发已授权的 STOP。

## 状态显示

右上角显示区始终保留，显示板端确认的运行状态、频率/循环说明、完成帧数及最近确认时间，覆盖：

- 未连接或状态未确认；
- 停止后的全0、全1或图案保持；
- 全0/全1慢速循环和硬件方波；
- MT 上传、一次播放、循环播放，以及 MT 全0/全1恒定循环；
- 256QAM上传进度、预检、一次/循环播放、单次结束保持及实际PWM/K/包CRC；
- 图案顺序、往返、随机播放；
- 输出禁能/高阻和执行异常。

配置草稿不会改变这个显示。MT 循环方式由本次已确认的下发记录补充；连接到已在运行的 MT 时，固件没有返回一次/循环字段，因此显示“MT 模式运行”，不猜测播放方式。

界面显示命令镜像与控制状态，保留原版的“不是物理电压回读”含义。连接和定时刷新只读取 STATUS。断开/退出会结束电脑端图案调度并关闭连接。新配套固件在连接变化时使未完成上传失效，已启动的硬件播放继续；重新连接查询实际状态，需要停止时再通过总按钮下发STOP。

## 256QAM 完整链路

上位机已接入 **MT时域控制 → 400路独立 / 256QAM**，与原统一MT配置独立显示、独立保存当前草稿。

- 导入码本目录/ZIP，或直接加载`../../QAM_RULES/256QAM` 中的0°码本；验证SHA-256、Gray映射、几何、脉冲表与全部二进制图案。
- 目标星座、所选单元PWM、逐时间片整板图案预览；点击星座/阵列只修改选择。
- 固定符号、HEX字节序列、二进制文件或00–FF测试序列；设置K和整序列一次/循环，显示符号率及一遍时长。
- “全板设置 → QAM方向与极性”保存旋转/镜像、高低状态对应及实物核对记录。默认不猜测方向与极性。
- 静态码片核线通过右上角总按钮下发，仍使用既有FRAME协议；屏幕明确显示静态保持。
- 导出完整离线播放配置包，包含引脚重排后的图案字典、持续时间表、原始数据和配置快照。

实时播放已接入新副本的TCP协议、ARM固件与QAM1 AXI播放器。总按钮先检查能力，再上传图案/时段/符号表/原始数据，CRC通过并经FPGA预检后播放。每次最多4096字节，可一次或循环，停止保持完整400位并能切回旧控制模式。

现有1 MHz码本仍不能原速播放；默认严格校验会拒绝下发。数字核线需明确选择“低速数字核线（明确改速）”，200 ns/片对应实际PWM 19.53125 kHz。2026-11-02配套镜像已完成Flash烧写、两次完整读回和断电启动检查；动态QAM与空口性能尚未实测。

优先阅读 [完整链路使用说明](docs/qam256_end_to_end.md)；导入、预览和来源ZIP格式见 [上位机使用说明](docs/qam256_host_usage.md)。码本核对结果见 [数据审计](docs/qam256_audit.json)。

## 独立QAM RTL

256QAM发送参数页新增“加载前导码MT表”，最多10个零延时周期。上位机将全板统一前导码和后续独立QAM编成同一条播放序列，每次整帧循环均包含前导码，使用已烧写的QAM1固件，无需重新烧写。格式、时序和容量说明见 [前导码使用说明](docs/qam256_preamble.md)。

新的RTL、AXI寄存器、C固件、编译和验证入口集中在 [FPGA/ris_qam_backend](../../FPGA/ris_qam_backend/README.md)。该副本增加400路独立图案播放器，保留原全板/统一MT功能。配套下载文件在 `../../FPGA/ris_qam_backend/export_qam/`；硬件与固件来源各有SHA-256清单。

Flash用的配套启动镜像为 [BOOT.bin](../../FPGA/ris_qam_backend/export_flash/20261102_qam/BOOT.bin)，包含FSBL、BIT和网络ELF；目标为ZC706双并行QSPI，写入偏移`0x0`。已完成烧写、两次完整读回与断电启动验收，记录见 [实板报告](../../FPGA/ris_qam_backend/reports/flash/FLASH_REPORT.md)。

## 64QAM（新增）

MT时域控制的控制类型新增“400路独立 / 64QAM”，与256QAM并列、配置独立。默认读取 `../../QAM_RULES/64QAM/ris_64qam_64slice_codebook`，160 kHz、64片、K=1，采用IIIQQQ六位Gray标签（每字节00–3F）。前导码和总下发方式保持一致。入口 `./start_gui.sh --qam64`；详见 [64QAM操作与时序](docs/qam64_usage.md)。

保持100 MHz SHCP及300 MHz内部时钟；64QAM将每周期编成1875个tick，边沿量化误差不超过约1.667 ns。256QAM原有路径保留。使用64QAM需要本次配套BIT/ELF，旧板端能力会在上传前被拒绝；新文件的构建结果见板端 `reports/qam64`。
