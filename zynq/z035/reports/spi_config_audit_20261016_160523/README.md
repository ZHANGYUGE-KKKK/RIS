# AD9361 SPI 配置核对与数据极性短测

2026-10-16，当前 xc7z035 / FMCOMMS3，原 FPGA BIT 与原 ARM 应用。

结论：SPI 可以控制时钟链、数字接口格式和相对延时，但本次没有发现明确的时钟分频或接口模式配置错误，也没有找到能修复 PRBS 的简单极性设置。当前配置不能仅凭 PLL 锁定或 FRAME 状态良好验收。

## 核对的是实际使用的初始化分支

`ad_config.h` 的 `AD_CONFIG_USE_CONFIG915=1`；`helloworld.c` 从 `main()` 进入
`config915_test_main()`，调用 `ad_config_init_915()`。因此：

- 实际使用 `config915_data.h` 中的脚本操作及执行器的板级适配。
- `AD_CONFIG_SAMPLE_HZ=61440000`、`radio_set.h` 的时钟反相/输入延时等参数属于另一初始化分支，不决定当前脚本配置。
- `config915` 原文件的 009=17 在执行时改为 07，使用板载晶体/DCXO；292=08、293=80、294=00 设置粗调 8、细调 4096。
- 执行器在脚本结束后设置 014=23 进入 FDD，并设置 TX1 BIST 音调；普通 RX 仍接收射频端口数据。

重新读回了 000..05F 和十个扩展寄存器。选定的 29 个稳定配置值全部与脚本最终值及显式板级适配相符。
原始数据：[spi_baseline.bin](spi_baseline.bin)，解析：[analysis.json](analysis.json)。

## 当前关键读回

| 项目 | 读回 | 判断 |
|---|---|---|
| 时钟使能 009 | 07 | 数字时钟/BBPLL 开启，XO_BYPASS=0，与晶体/DCXO 方式一致 |
| DCXO 292/293/294 | 08/80/00 | 粗调 8，细调 4096，与执行器一致 |
| BBPLL 041/042/043/044/045 | 12/5C/29/18/00 | 按 40 MHz 参考计算，BBPLL 约 983.04 MHz |
| ADC 分频 00A | 02 | BBPLL / 4，ADC 约 245.76 MHz；DAC 不再二分频 |
| 通道与滤波 002/003 | DE/DE | 两收两发使能；RX/TX 各级倍率均为 2，最终 Fs 约 15.36 MSPS |
| 接口 010/011/012 | C8/00/10 | 与 UG-570 图 79 的 2R2T LVDS DDR 例子一致 |
| FPGA 模式 82000044 | 00000000 | 2R2T；四路 PN 选择寄存器均为 0，选择 AD9361 专用序列检查 |
| PLL 状态 05E/247/287 | 80/02/02 | BBPLL、RX RFPLL、TX RFPLL 均显示锁定 |
| RX 时钟/数据延时 006 | 0F | 时钟延时码 0，数据/FRAME 延时码 15；合法，但未证明是本板有效采样点 |
| LVDS 偏置 03C | 21 | 驱动幅度设置为 150 mV；AD9361 输入端片内终端开启 |
| LVDS 极性 03D/03E | 00/00 | 不同于 UG-671 推荐的 FF/0F，需要结合实际接线判断 |

接收时钟链（MHz）：

```text
BBPLL 983.04 → ADC 245.76 → RHB3 122.88 → RHB2 61.44 → RHB1 30.72 → FIR 15.36
```

以上频率来自寄存器计算，并假定实际晶体参考为 40 MHz；PLL 锁定不能代替引脚频率/波形测量。
在当前普通双通道 LVDS 4Fs 传输模式下，DATA_CLK 名义值为 61.44 MHz。
00A 的 CLKOUT Select 控制另一个 CLK_OUT 引脚，不能把它当作 DATA_CLK 的直接分频开关。

## 两处容易误解的配置

1. **010 的 2R2T Timing 位为 0，并不表示当前是 1R1T。**
   UG-671 说明：该位为 1 时强制 2R2T 时序，为 0 时按实际使能通道决定。
   当前 002/003 都启用了两路，所以 C8 与 2R2T 并不矛盾。
2. **03C 的 Rx On Chip Term 不会给 FPGA 接收端加终端。**
   此处 Rx 指 AD9361 的 LVDS 输入接收器，作用于 FPGA→AD9361 的数据、TX_FRAME 和 FB_CLK。
   AD9361→FPGA 的 RX_DATA、RX_FRAME、DATA_CLK 是否有合适终端，需要在 FPGA/PCB 侧确认。
   03C 的驱动幅度可以经 SPI 改变，但本轮没有调整它，也没有证据证明 150 mV 就是故障源。

## 推荐数据极性的四组短测试

UG-671 第 18 页说明：默认的数据差分对极性反向，建议 03D=FF、03E=0F；
时钟和 FRAME 的默认极性不反向。具体是否适用仍取决于板上 P/N 接线。
本轮保留 FRAME/DATA_CLK 物理极性位，只比较数据相关的极性设置，并交叉比较 010 的时钟反相位。

全程 ARM=0、DMA 停止，006 固定为原值 0F，FPGA 七路延时不变。
暂时启用 RX PRBS（3F4=09、3F5=00、3F6=00），每组等待 2 ms，计数约 5 ms，再运行原有 PN 检查 10 ms。

| 010 | 03D/03E | PRBS | 四路通道状态 | FPGA 内部估算 RX 边沿率 |
|---|---|---|---|---|
| C8 | 00/00，原数据极性 | 失败 -4 | 02/02/02/02，失步 | 178.86 MHz |
| C9 | 00/00 | 失败 -4 | 02/02/02/02，失步 | 144.63 MHz |
| C8 | FF/0F，手册推荐 | 失败 -4 | 02/02/02/02，失步 | 179.02 MHz |
| C9 | FF/0F | 失败 -4 | 02/02/02/02，失步 | 145.44 MHz |

这说明：只改数据极性不足以修复当前故障；它没有消除计数随时钟反相明显变化的现象。
本次只在 006=0F 下比较四组，不代表对 FF/0F 配置完成了全部延时校准。
本轮没有抓取新的 ILA，因此不对四组条件下逐周期 FRAME 瞬态变化作结论。
上述频率仍来自内部数字计数，不能直接视作引脚实际频率。

## 下一步判断

- 当前频率规划与接口模式具有一致性，暂时没有依据直接改成另一套 BBPLL 或 1R1T 配置。
- SPI 调相本来就可能修复建立/保持时间不足，参见 AN-1441；但此前原数据极性下的全延时扫描没有通过点，本次数据极性短测也没有通过点，所以尚不能承诺单改 SPI 可解决。
- 如继续软件排查，应把手册推荐数据极性与本板的采样校准结合验证；如仍全失败，应优先独立核对 DATA_CLK 测量与输入波形，区分输入信号问题和 FPGA 计数/采样问题。

## 恢复及验证

- 006、010、03D、03E、3F4、3F5、3F6 均逐项保存、恢复并回读，恢复结果 0。

- ARM 保持 0。最终快照 GPIO=01，脚本结束时 GPIO=03；bit1 是瞬时接口状态，因此允许在二者之间变化。READY 为 1，无 ACTIVE/溢出/帧错误/延时错误锁存。
